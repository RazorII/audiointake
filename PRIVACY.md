# Privacy

audiointake and its Claude plugin collect no data.

- **Your recordings stay on your Mac.** audiointake reads them, transcribes them and writes the transcripts there. No audio, no transcript text and no voiceprint ever leaves it through audiointake.
- **Transcribing never goes online.** `audiointake transcribe` makes no network connection at all: the models are loaded from files already on your Mac, and every program it starts gets an environment with Hugging Face's online features switched off (`HF_HUB_OFFLINE=1`). The same holds for `relabel`, `notes`, `enroll`, `voices`, `record`, `doctor`, `about` and `uninstall`. No AI service is ever called.
- **No telemetry.** No analytics, no crash reports, no account. Two of the libraries audiointake uses would send usage data by default, onnxruntime (inside sherpa-onnx) to Microsoft and huggingface_hub to Hugging Face; audiointake switches both off (`ORT_DISABLE_TELEMETRY=1`, `HF_HUB_DISABLE_TELEMETRY=1`) before either is loaded, in its own process and in every program it starts.
- **The only network traffic is installing and setting up.** audiointake connects to these hosts and no others:
  - `huggingface.co` and its download hosts under `hf.co` (seen so far: `us.aws.cdn.hf.co`): the speech, language and diarization models, at `audiointake setup`, and when you add a language pack (`audiointake setup --pack`, or `audiointake apply --lang` for a pack you asked for). Every file is downloaded at a pinned revision and checked against its pinned fingerprint. **No Hugging Face token is ever sent**: audiointake doesn't read `HF_TOKEN` or a stored Hugging Face login, and sends no `Authorization` header.
  - `github.com`, and `objects.githubusercontent.com` and `release-assets.githubusercontent.com`, where GitHub serves release files from: at setup, the speaker program's source ([FluidAudio](https://github.com/FluidInference/FluidAudio), fetched by its pinned commit), the prebuilt text-processing library it links, and the CAM++ speaker-recognition model.
  - `groups.inf.ed.ac.uk`: once, at setup, 30 seconds of a public test recording from the [AMI Meeting Corpus](https://groups.inf.ed.ac.uk/ami/corpus/), kept so later self-tests (`audiointake doctor --selftest`) work offline. If it can't be fetched, setup carries on without it.
  - Installing audiointake itself: `github.com` and `codeload.github.com` (the release's source archive), and uv's `pypi.org` and `files.pythonhosted.org` (the Python libraries). When uv needs to fetch Python itself (the install asks for Python 3.14, and uv fetches it when the Mac has none), it downloads it from `releases.astral.sh`, Astral's mirror of the Python builds, and only if that fails from `github.com` and `release-assets.githubusercontent.com`. The Claude plugin installs uv, when it's missing, from `github.com` and `release-assets.githubusercontent.com`.

  If you use an HTTPS proxy (`https_proxy`), setup's downloads go through it: it's your own route to the internet, and the pinned fingerprints mean a proxy can't change what's installed.

  These hosts see what any download shows them: your IP address and the file you asked for, never anything about your recordings. A language pack's download names only the pack, and happens only when you ask for that pack, never because a recording seemed to be in its language. Their own privacy policies cover that ([Hugging Face](https://huggingface.co/privacy), [GitHub](https://docs.github.com/en/site-policy/privacy-policies/github-general-privacy-statement), [PyPI](https://policies.python.org/pypi.org/Privacy-Notice/), [Astral](https://astral.sh/legal/privacy), [the University of Edinburgh](https://www.ed.ac.uk/about/website/privacy)).
- **Transcripts are your files.** `<name> (transcript).md` and `<name> (transcript).json` (and `.txt` if you ask for it) are written next to each recording, or in the folder you name. If that folder is synced (iCloud Drive, Dropbox) or shared, the transcripts go wherever it goes, like any other file there. `<name> (notes).md` is the same.
- **What audiointake keeps on your Mac.** In `~/Library/Application Support/audiointake/` (or `AUDIOINTAKE_HOME`), folders readable only by you:
  - `records/`: a **record** of each run. It holds the recording's path, size, duration and SHA-256 fingerprint, the options, the outputs' paths and fingerprints, the models used, counts and timings, warnings, notes and offers, and the speakers' labels with the **names of speakers a voiceprint recognised** or you gave. **It never holds transcript text**: no sentence, turn, word or model output. Records are deleted after 90 days.
  - `voices/`: your **voiceprints**, one file per person (`name.json`, readable only by you): the person's name, the speaker model's fingerprint, and for each recording enrolled, a list of numbers that describes the voice, a description of the source (a file name and a time range), its length in seconds, its language and the date. Never any audio. Outside iCloud Drive. `audiointake voices remove NAME` deletes one.
  - `models/`: the models audiointake converts or assembles itself (the Thai model converted to MLX, the diarization model's folder, the CAM++ speaker model).
  - `tools/`: the speaker program built on your Mac, with a note of how it was built.
  - `packs/`: for each installed pack, the paths, sizes and fingerprints of its files as setup verified them; every run checks that the files haven't changed since.
  - `canary/`: the 30-second public test recording.
  - `speed.json`: how fast this Mac transcribes, for time estimates; numbers only.
  - `downloads.json`: the model files audiointake downloaded itself, so that removing a pack or uninstalling deletes only those, never models that were in your Hugging Face cache before.
  - `run.lock`: an empty file that keeps two runs from writing at once.

  In `~/Library/Caches/audiointake/` (or `AUDIOINTAKE_CACHE`): `work/`, one folder per run for its temporary audio and intermediate files, deleted when the run ends (any left behind by a crash are deleted at the next start, after a day), and `build/`, the speaker program's build folder, deleted once it's built.

  In `~/Library/Logs/audiointake/`: one log per run, with step timings, model tags, codes, and the last lines a failing helper program printed as an error, never transcript text. Deleted with its record, after 90 days.

  Models go to the standard Hugging Face cache (`~/.cache/huggingface/hub`, or `HF_HUB_CACHE`), where other tools on your Mac can use them too.

  `audiointake uninstall` removes all of this except the models that were in your Hugging Face cache before audiointake came (and, with `--keep-voices`, your voiceprints). Your transcripts and notes are yours and stay where they are.
- **Backups.** Time Machine backs up `~/Library/Application Support/audiointake/` like the rest of your Library, voiceprints included. Deleting a voiceprint doesn't reach a backup made before.
- **Claude itself is covered by Anthropic's privacy policy.** When you use audiointake through Claude, what Claude does with your conversation falls under [Anthropic's privacy policy](https://www.anthropic.com/legal/privacy), not this one. To write notes, or to tell you what was said in a recording, Claude reads its transcript, and the text goes to Anthropic as part of the conversation; say "just transcribe" and Claude won't read it. Claude also sees what the command prints, even then: file names and paths, how long each recording is, warnings, the names of recognised speakers, and, when it lists or makes voiceprints, their names and what each was made from (a file name and a time range). File names can say a lot, so choose them knowing that. For a recording that's in iCloud Drive but not on your Mac yet, Claude asks macOS to download that one file from your iCloud Drive (`brctl download`), as Finder's Download Now does. When speaker labels need Apple's Command Line Tools, Claude may start Apple's own installer for them, which downloads them from Apple.
